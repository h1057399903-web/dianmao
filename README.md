# 点卯 dianmao

omp 扩展：主会话每分钟清点一次 task 小工（子代理），出问题就把报警作为 aside 消息送进主会话（主会话空闲时会直接唤醒它）。点卯只观察和报告；重试、催办、换人由主会话决定。

报警卡片区分“疑似卡住”“疑似空转”和“模型重试受阻”，按小工、证据、建议分行显示。默认只显示记录文件名；展开详情显示完整路径。主模型收到的报警仍保留完整路径，旧消息继续使用默认渲染。卡片复用 OMP 的 TUI 组件（`@oh-my-pi/pi-tui` 18.10.4 或兼容版本）。

| 情况 | 判断方法 | 默认 |
|---|---|---|
| 卡住 | 最后一条对话消息多久没更新（不看文件修改时间，收工后的用量探测会刷新它）。正在跑显式设了长 `timeout` 的命令时，等到它的截止时间 + 2 分钟；命令返回后恢复默认 | 20 分钟 |
| 空转 | 从第一次看到小工起，每个固定窗口把这段时间的操作摘要交给 SubQ，问"有没有可核对的进展" | 每 30 分钟、至少 10 次操作、概率 < 0.2 报警 |
| 模型重试受阻 | 同一模型连续返回限流／额度错误；识别直接 429、503 等外层状态码中包含的 429，以及额度耗尽错误正文。不把工具输出中的“429”当成模型错误 | 至少 3 次、从本轮首次错误起至少 5 分钟未恢复 |

不算在岗、不会报警的：`<名字>.md` 结果文件不早于最后一条消息、最后一条是最终回复 / 被取消 / 单次报错、有 `session_exit`、超过 6 小时没动、`__advisor*` 记录。重新开工后，旧结果文件不再遮住新的对话记录。连续两次以上报错（harness 在自动重试，如模型额度用尽）算在岗，闲置从第一次报错算起，重试不刷新计时。

同一次卡住只报一次。单个记录读不了（坏行、刚被移走）只跳过它，下一轮再看。SubQ 失败或超时就跳过这个窗口；等回答期间小工收工、换了会话或已进入下一个窗口，旧结论直接丢弃。

额度重试报警不调用 SubQ、不发送原始错误正文。同一轮只报一次；模型恢复或收到新任务后重新计数，取消或退出后不报。只建议主控检查额度、等待恢复或调整模型配置，不自动换模型、重试或停止小工。

`timeout: 0` 表示工具没有截止时间，不表示永远健康：仍按默认闲置阈值提醒。长任务可能被提醒，点卯不会自动取消或重试它。

**发给 SubQ 的内容**：每次调用只有工具名、成功/失败/进行中、耗时、模型自己写的一句意图（截到 60 字），以及参数指纹（参数相同则指纹相同，看不出内容）。原始命令、路径、文件正文都不发送。

## 安装

```sh
omp plugin install github:h1057399903-web/dianmao
omp plugin upgrade dianmao   # 以后更新
```

重开 omp 窗口生效，之后每个新窗口都自动带上。本地改代码时用 `omp plugin link /path/to/dianmao` 代替。

SubQ 密钥：优先读环境变量 `SUBQ_API_KEY`，否则读 macOS 钥匙串条目 `omp-subq-snap`（和 subq-snap MCP 共用）。都没有时仍会检查卡住和模型额度重试，只跳过 SubQ 空转判断。

## 调参（环境变量）

`DIANMAO_STALL_MIN` `DIANMAO_WINDOW_MIN` `DIANMAO_SPIN_MIN` `DIANMAO_SPIN_MIN_OPS` `DIANMAO_SPIN_THRESHOLD` `DIANMAO_POLL_SEC`
