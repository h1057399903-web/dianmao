# 点卯 dianmao

omp 扩展：主会话每分钟清点一次 task 小工（子代理），出问题就把报警作为 aside 消息送进主会话（主会话空闲时会直接唤醒它）。点卯只观察和报告；重试、催办、换人由主会话决定。

报警卡片区分“疑似卡住”“疑似空转”“模型重试受阻”和“施工进展待核对”，按小工、证据、建议分行显示。默认只显示记录文件名；展开详情显示完整路径。主模型收到的报警仍保留完整路径，旧消息继续使用默认渲染。卡片复用 OMP 的 TUI 组件（`@oh-my-pi/pi-tui` 18.10.4 或兼容版本）。

| 情况 | 判断方法 | 默认 |
|---|---|---|
| 卡住 | 最后一条对话消息多久没更新（不看文件修改时间，收工后的用量探测会刷新它）。正在跑显式设了长 `timeout` 的命令时，等到它的截止时间 + 2 分钟；命令返回后恢复默认 | 20 分钟 |
| 空转 | 固定窗口内，把任务目标摘录、操作类别、完成状态、测试结果趋势与相同操作的结果变化交给 SubQ；同一次请求同时判断“有没有进展”和“证据是否充分” | 每 30 分钟、至少 10 次操作；证据充分概率 ≥ 0.7 且进展概率 < 0.2 才报警 |
| 模型重试受阻 | 同一模型连续返回限流／额度错误；识别直接 429、503 等外层状态码中包含的 429，以及额度耗尽错误正文。不把工具输出中的“429”当成模型错误 | 至少 3 次、从本轮首次错误起至少 5 分钟未恢复 |
| 施工进展待核对 | 任务有明确的修改要求，但从派工或最近一次记录到的成功修改起，长期未见新的成功修改操作。只请主控核对，不直接判为空转；不依赖 SubQ、操作次数或首次巡检时间 | 60 分钟 |

不算在岗、不会报警的：`<名字>.md` 结果文件不早于最后一条消息、最后一条是最终回复 / 被取消 / 单次报错、有 `session_exit`、超过 6 小时没动、`__advisor*` 记录。重新开工后，旧结果文件不再遮住新的对话记录。连续两次以上报错（harness 在自动重试，如模型额度用尽）算在岗，闲置从第一次报错算起，重试不刷新计时。

同一次卡住只报一次。坏行跳过，单个记录读取失败只影响该小工；读取失败数可在 `/dianmao` 查看。SubQ 失败、超时或证据不足时不判为空转，状态中显示未形成结论或请求失败，而不是宣称正常；施工核对提醒仍独立生效。等回答期间小工收工、产生新消息、换了会话或任务，旧报警直接丢弃。新任务重新积满 SubQ 观察窗口，主控补充消息不会刷新原任务的施工计时。

额度重试报警不调用 SubQ、不发送原始错误正文。同一轮只报一次；模型恢复或收到新任务后重新计数，取消或退出后不报。只建议主控检查额度、等待恢复或调整模型配置，不自动换模型、重试或停止小工。

`timeout: 0` 表示工具没有截止时间，不表示永远健康：仍按默认闲置阈值提醒。长任务可能被提醒，点卯不会自动取消或重试它。

施工核对识别非只读目标中的 `# Change` / `# Implementation` / `# 修改` / `# 实现`，或以“实现／修复／新增／添加／修改／implement／fix／add／build”开头的目标。成功完成的 `edit`、`write`、`ast_edit` 才重置计时；失败、后台运行和 `xd://` 写入不算。仍在显式长工具超时豁免期内时暂不发这类提醒；同一计时起点只提醒一次，成功修改后重新计时。**这不是 Git diff 检查**：shell 脚本内部修改可能无法识别，持续有效的排查也可能收到核对卡片，主控应核对根因或产物，不能据此自动停止小工。

记录首次从头解析，之后按追加的 JSONL 增量读取；保留任务目标、未返回工具和最近的操作元数据，不再只看最后 512KB。工具返回可以跨读取块、跨巡检轮次配对；半写入行和 UTF-8 字符保留到下次读取。文件替换、截断或游标边界改变时重建状态。原始施工目标保留 `Target` 与 `Change` 的限长摘录，不会被普通主控补充消息覆盖。

**发给 SubQ 的内容**：

- 当前任务目标的文字摘录（最多 400 字符）、操作意图（最多 120 字符）；过滤代码块、内联引用、常见凭据、链接与绝对路径。
- 最近至多 40 次操作的类别、成功／失败／后台运行状态、耗时，以及记录中可提取的退出码、超时标志、测试通过／失败数。
- 参数与结果的带进程随机密钥指纹，用于比较相同请求和结果变化；不转发原始参数、命令、代码或工具输出正文。

测试数字只是工具报告，不代表独立验证。成功的工具调用、变了的指纹，不自动等于任务有进展；只读审查无需修改文件才算正常，后台启动也不冒充任务已完成。找不到目标就明确告知 SubQ 未知，不编造目标。这里的目标与意图仍是自然语言摘录，常见凭据过滤不是完整的数据防泄漏系统，可能保留业务信息。

## 安装

```sh
omp plugin install github:h1057399903-web/dianmao
omp plugin upgrade dianmao   # 以后更新
```

重开 omp 窗口生效，之后每个新窗口都自动带上。`/reload` / `/reload-plugins` 不会给旧进程重新加载扩展代码，不能代替重开。加载后底部显示点卯版本及最近巡检时间；输入 `/dianmao`（也可 `/dianmao status`）查看版本、最近成功巡检、在岗记录数、读取失败数与最近 SubQ 状态。首次巡检默认在加载后 60 秒；“等待首次巡检”不等于已经检查过。旧版本没有此命令或版本标记，不能仅凭“插件已安装”认定该窗口正在巡检。本地改代码时用 `omp plugin link /path/to/dianmao` 代替。

SubQ 密钥：优先读环境变量 `SUBQ_API_KEY`，否则读 macOS 钥匙串条目 `omp-subq-snap`（和 subq-snap MCP 共用）。都没有时仍会检查卡住、模型额度重试与施工进展待核对，只跳过 SubQ 空转判断。
